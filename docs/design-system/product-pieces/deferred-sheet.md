# Deferred sheets

- Shell entry points never import a sheet flow statically. They mount it through `deferSheet` (`client/money-modal/deferred-sheet.tsx`), so each flow's code stays in its own lazy chunk. A journey whose entry is a static management tray defers only its nested money step with `deferStep` and imports that step dynamically, as Save does, so the step code still stays out of the shell. The shared `MoneyModal`/Drawer host is already in the Home shell bundle (Borrow overview renders it), so the loading shell below adds no startup code on shell routes.
- Triggers spread `moneySheetIntent(preload, …)` (from `@/client/money-modal`): pointer-down and focus preload the sheet's code, so a touch first tap never depends on hover. Home primary actions (Send, Add money) also idle-preload their code once the account is verified. Idle work is code only; no API request, prepare, quote, provider session or wallet prompt runs on idle, hover or focus.
- Intent may also prefetch safe read-only data through the same query options the open sheet uses, so the cache key cannot drift. Add money prefetches funding providers and the open-order read (`client/funding/funding-prefetch.ts`), keyed by owner and region, only for a verified owner in a ready, non-global region, and never provider-customer reads or POSTs. Opening reuses fresh data within its stale time.
- Pass a loading shell as the second `deferSheet` argument with `moneySheetLoading({ title, titleId, closeLabel, onCancel, onClosed, placeholder? })` (from `@/client/money-modal`). A tap before the chunk arrives opens the canonical sheet immediately with the flow's real title, X, and a placeholder; a placeholder shaped like the first step (Add money's method list, `client/funding/method-skeleton.tsx`) avoids a height jump at handoff. After automatic retries fail, the shell shows Try again. X cancels the presentation; a chunk that arrives later mounts closed and never reopens or navigates. When the chunk arrives while the shell is visible, the loaded sheet replaces it in place without replaying its entrance, and focus stays inside the sheet and later returns to the original trigger.
- Data-dependent content loads inside the visible sheet with stable, sized placeholders and in-sheet Retry. Asynchronous data never auto-selects a method or navigates into a provider; only an explicit return-from-provider resume may continue an order.
- Keep Drawer-backed sheets mounted while driving `open`, and clear caller state only from the close-complete callback so exit motion runs. `deferSheet` stages a sheet that mounts already open through one closed render so entrance motion runs on first, preloaded, and repeat opens; a keyed replacement of an already-open sheet (an account-boundary remount) stays open without replaying its entrance. Reserve `immediate` for reduced motion and privacy drops (Send owner change).
