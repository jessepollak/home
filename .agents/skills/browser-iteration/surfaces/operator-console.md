- **Entry context**: operator · `/admin`, `/admin/{customers,support,growth,money,settings,settings/products,audit}`, `/admin/settings/funding` · signed native Home operator session · fixture session signs the placeholder operator address for the shared fixture routes; operator allowlist and signed native session (browser admin.pw.ts) · `/admin/support` entry.
- **Live**: read-only (operator authorization required); take-over/reply/resolve/reopen/hand-back steps are fixture-only.
- **Owned paths**: `apps/web/app/admin/**`, `apps/web/client/admin/**`, `apps/web/client/operator/**`, `apps/web/client/operator-support/**`, `apps/web/components/ui/rail-nav.tsx`, `apps/web/config/operator-navigation.ts`, `apps/web/server/operator/setup.ts`, `apps/web/shared/operator/setup.ts`
- **Setup walk — fixture (credential-free)**:
  1. `goto "/admin"`; expect **Overview → Setup**, Required and Optional lists, a required-step count, **Database → Missing** with `DATABASE_URL: unset`, and **Running version → Build metadata is absent (local or self-hosted build)**.
  2. In Setup, follow **General settings** (`/admin/settings`), **Products and markets** (`/admin/settings/products`), and **Money in and out** (`/admin/settings/funding`), returning with Back to Overview between links. Keyboard Enter must navigate, Back must restore Setup, and the 390px layout must not overflow.
  3. Optional Prices and provider/keyring rows may be Missing; optional rows do not increase the required-step count. Do not configure real credentials or save settings in this fixture.
- **Setup walk — live (read-only, administrator authorization required)**: Open `/admin` on the authorized deployment, inspect required/optional Setup states and Running version, follow the Settings links, and return. Missing/Invalid variables require private hosting configuration and a redeploy, not an in-app mutation; environment changes and redeploys need separate operator authorization. A configured but failing database shows **Unavailable**, distinct from **Missing**. Verify commit, branch, environment and deployment ID when build metadata exists; do not infer a commit when it is absent.

- **States**: Setup required rows are Ready, Missing or Invalid; Database additionally has Needs migration (production redeploy; manual path in Setup instructions) and Unavailable (configured connection/check failed). Missing Database means `DATABASE_URL: unset`; Unavailable means configured, not absent. Optional rows carry Optional and Ready/Missing/Invalid states without blocking required completion. Required-step count decreases only for required Ready rows; reload recomputes progress after private environment changes/redeployment, with no saved wizard state. Running version is deployment metadata or Build metadata is absent, never a branch-based guessed commit. Ordinary fixtures cover Missing database and absent build metadata; configured database failures and deployment metadata require a provisioned read-only session or a controlled local fixture. Support inbox unchanged-first-page polls atomically refresh through loaded depth, remove deeper rows outside the active filter and preserve the next unseen cursor; a deep-page failure/repeated cursor retains prior rows with Try again, traversal is bounded to 100 pages, and superseded/filter-change/unmounted requests cannot publish. Changed-first-page and visibility refresh reset depth. Loading skeleton; error with `Try again`; Settings review drawer lists offered country changes and their effects; a conflict closes review, preserves the draft and updates the saved baseline; Invest category/asset toggles, a hidden category collapses its asset rows and keeps their individual choices, dirty draft/save pending/saved, 409 conflict adopts the latest value as both baseline and draft so the operator must re-apply their change, failed save allows retry; deployment and saved provenance, exit-only locked children, orphan IDs, 409 conflict/reload, enable review/cancel; `/admin/nope` and nested unknown paths are uncached 404s showing `Page not found` and `Back to Overview`, with no current link.
- **Money in and out** (`/admin/settings/funding`, linked from the Settings index; stories `journeys-admin-funding-settings--*`): deployment-values banner or last saved by/at; provider credential names as set/unset, never values; corridors by region as Connected, off / On / Not connected, with New for corridors added since the last save; `PEER_OFFRAMP_ENABLED` as in effect or set but ignored; notice for saved corridors no longer in the catalog. A not-connected corridor shows its switch on when its saved selection is on, labelled `Not connected · On when credentials are set`, and that switch can be turned off (pausing it) even though turning one on always needs credentials — a disconnected, off corridor's switch stays disabled, and losing a credential clears a pending activation with a notice. Turning any corridor on opens a review (credential status, the evidence note of every provider binding the switch covers, or `none recorded`, and what customers see) and applies only on Confirm; the review also groups corridors recorded on without credentials; pause-only saves confirm inline, naming disconnected corridors being paused and saying such a corridor stays off when its credentials return. States: saved, conflict (Save disabled until the latest settings load), uncertain save result, settings unavailable. Fixture sessions can reach it, but saves need a provisioned database; verify in Storybook, then on an operator session.
