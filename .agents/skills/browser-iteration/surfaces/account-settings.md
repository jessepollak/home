### `account-settings`
- **Entry context**: account · `/?account=settings` (dashboards commit `?account=settings`, shell.tsx `openAccountSettings`) · signed-in verified · signed-in seed · header profile mark (`ProfileMark`, shell-chrome.tsx) → settings; or goto `/home?account=settings`.

- **Live**: read-only
- **Owned paths**: `apps/web/client/account/account-settings.tsx`, `apps/web/client/identity/**`, `apps/web/client/home/shell-panels.tsx`, `apps/web/client/home/use-show-small-balances.ts`, `apps/web/client/appearance/**`, `apps/web/shared/appearance/**`
- **Reach**:
  1. `goto "/home?account=settings"`
  2. `expect "Account"`
- **Notes**: The fixture-session helper seeds signed-in state and fixtures. The Chromium smoke opens the header profile mark with the keyboard, asserts focus enters the settings region, closes through Done and browser Back, restores the exact opener, exercises deep-link and forward-history entry, and verifies every primary-navigation `aria-controls` target remains unique and present. Live: Peer availability varies by deployment and corridor (`PEER_OFFRAMP_ENABLED`, `apps/web/server/funding/providers/peer/manifest.ts`). Production exposed the Cash App path and a live review on 2026-09-24; snapshot current provider availability rather than assuming it is off.
- **Expect**: region `aria-label="Account settings"` receives programmatic focus without selecting an input; `Show small balances` switch (`getByRole("switch", { name: "Show small balances" })`, mobile-geometry.pw.ts; owned by client/home/use-show-small-balances.ts + account-settings region of shell-panels.tsx). `Appearance` radiogroup (`getByRole("radiogroup", { name: "Appearance" })`) has Light, Dark, and System radios, with one checked; selection updates immediately via shell.tsx. Sign-out control and region selector live here (shell-panels.tsx passes `regionId`, `resolutionSource`, `onRegionChange`, `onSignOut` to client/account/account-settings.tsx).
- **States**: preference not ready (`isPreferenceReady`); region override messages (`preferenceMessage`); appearance Light / Dark / System (including system changes) and storage-unavailable announcement in the polite preference status; narrow 320px row wraps the radiogroup under its title. Identity row (client/identity/identity-row.tsx, fixture `GET /api/identity/verification` returns `not-started`, shown as `Not verified`): `Verify identity` opens the `Verify identity` sheet with one Sumsub consent line and `Continue`; other states (`In progress — continue`, `Checking your details`, `Under review`, `Verified` + date, `Needs more from you` + reason, `Verification could not be approved` + `Contact Home support`, removed `Not verified` + `Verify again`, `Temporarily unavailable`, `Identity verification isn't available right now`) need a route override of that endpoint. `Continue` posts `/api/identity/verification/session`; without a fixture for it the sheet closes and the row shows `Temporarily unavailable`, never a rejection. With a routed session token and `**sumsub.com/**` aborted, the embedded flow falls back to `Continue in a new tab` after about 12 seconds (provider simulated).
- **Evidence**: screenshot; DOM snapshot; console/errors.
- **Owned by**: `apps/web/client/account/account-settings.tsx`, `apps/web/client/home/shell-panels.tsx`.
- **Unknowns**: the country selector is described by `Country` / `Sets how money is shown`, and the button is labelled `Sign out`. The embedded Sumsub flow and hosted link are provider-hosted and cannot be reached with fixtures; exercise them only in the operator's sandbox trial.
