### `support-chat`
- **Entry context**: account · `/home?account=settings` → Support · signed-in verified · signed-in seed with `/api/support`, `/api/support/summary` and the local fixture `/api/support/chat` stream (`HOME_PLAYWRIGHT_SMOKE=1`) · Account settings Support row, or Message support from a funding failure notice.
- **Live**: read-only (do not send a real customer message without explicit authorization).
- **Owned paths**: `apps/web/client/support/**`, `apps/web/components/ui/{support-message,prompt-input,conversation}.tsx`, `apps/web/client/home/{shell,shell-chrome}.tsx`, `apps/web/components/{profile-mark,primary-navigation}.tsx`, `apps/web/client/account/account-settings.tsx`, `apps/web/client/account/cdp-authenticated-transport.ts`, `apps/web/client/funding/order-flow.tsx`.
- **Reach**:
  1. `goto "/home?account=settings"`
  2. `click "Support"`
  3. `expect "How can we help?"` (the fixture advertises an available assistant; operator-only mode shows Send us a message. instead)
- **Expect**: The Support drawer is a deferred sheet: it opens immediately on a labelled loading skeleton (a close control included) while its chunk loads, so the chat is absent from Home's first paint; a chunk that cannot load leaves `Couldn't open support.` with `Try again`. Inside it, a polite message log sticks to the newest message unless the customer scrolled up (then `Scroll to latest message` appears). Customer messages are right-aligned bubbles; replies are left-aligned plain text labelled `Assistant` or `Support` (a person). With the assistant available the empty state shows three suggested questions that send on tap. The composer is labelled `Message support`; its round Send button becomes `Stop` while a reply is pending or streaming. In hybrid mode `Talk to a person` sits in the header while the assistant handles the chat; after handoff the header control disappears, focus moves to the composer and `A person will reply here.` shows above it. Unread count appears on the Account row, the header profile button and the desktop rail Account button accessible names; an unknown summary shows no badge, and a failed summary shows `Couldn't check messages · Retry` on the Account row. Funding failure entries show `About your add money order` without exposing the order ID. Enter sends on pointer-fine devices; Shift+Enter inserts a newline. The composer limits messages to 2000 characters.
- **States**: deferred chunk loading skeleton and `Couldn't open support.` retry; message loading skeleton; empty with suggestions; operator-only empty; assistant streaming (Stop); assistant reply; hybrid handoff and failed handoff; operator reply and read acknowledgement; send failure → Not sent · Retry (same message ID and context); 429 → Too many messages; assistant failure → The assistant couldn't reply · Try again; discarded reply removed after an operator takes over; load failure → Try again. Polling runs every 5 s while open and visible and pauses while hidden, closed or streaming. Past one 50-message page the log offers `Load earlier messages` and merges older pages ahead of the live page; the loaded history resets when a newer message shifts the page boundary.
- **Evidence**: screenshot at mobile (390×844) and desktop (1280×800); DOM snapshot; console/errors.
- **Owned by**: `apps/web/client/support/**`.
- **Unknowns**: the fixture chat stream returns one canned assistant reply and persists nothing, so a reload shows an empty conversation again; use the `Journeys/Support chat` stories for streaming, handoff, operator reply, failure and rate-limit states rather than a live send.
