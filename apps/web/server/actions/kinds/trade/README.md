# CDP Swaps on Base (#616, #980)

Any exact Base ERC-20 other than USDC or a tokenized stock can request a USDC-paired trade. A quote determines availability per amount and route; there is no catalog gate or liquidity floor. `resolveTradeAsset` validates asset identity, `buy-policy.ts` holds the operator-removal seam enforced at availability, prepare and first confirmation (buys only; replay unchanged), and `erc20-execution-identity.ts` reads code, decimals and optional wallet balance from chain. Configured decimals must match chain decimals. Display prices and indexed balances never supply execution amounts.
Cash-currency trade/Convert admission additionally requires verified pair records in both directions for the exact registry currency and USDC. A registry cash contract without them is not tradable, even when a provider offers a route. Availability and preparation enforce admission, and the first confirmation re-checks it from stored metadata before signature verification, failing closed with `TRADE_ADMISSION_REVOKED` (409) if no longer admitted, distinct from quote or review expiry (`ACTION_EXPIRED`). Buy-only operator removal uses the same confirmation refusal. The client shows the trade or conversion as unavailable with a way back and no automatic re-quote or Get new quote; a prepared trade stores the registry currency it was prepared against, so removing that record also fails the confirmation closed instead of reading the contract as a foreign token. Already-confirmed actions replay their stored calls subject to the existing replay checks.

`GET /api/trades?assetId=<id>` privately reports provider, account, signer and token readability, the current chain balance and buy policy. `prepare.ts` verifies signer and token identity at latest, converts sell-all using the chain balance, requests an executable quote and checks the pinned Base block, registry Settler, Permit2 nonce, RFQ maker permits, balance and allowance. A full sell whose pinned balance falls below the latest read fails; it never issues a partial review. The audited `fees` settings domain determines the trade fee at prepare; a failed settings read fails closed as `TRADE_UNAVAILABLE`. With an active rate and destination, buys quote on net USDC (gross input minus floor-rounded fee), bind the net to Permit2, check gross against the wallet balance, and show gross as customer spend. Sells quote on the full token input and deduct a fee calculated from minimum USDC output from the estimated customer receive. The active in-batch-transfer strategy inserts exactly one USDC transfer to the configured destination: buys place it before Permit2 approvals and the swap, sells after the swap. A paymaster approval, when selected, remains first. Both calls execute atomically; issuance verifies fee metadata against exact transfer calldata and the signed swap index. Zero or rounded-zero fees omit the call and fee record. A provider-native strategy interface passes the rate and recipient to a provider quote without a separate call, but is not selected for CDP Swaps: CDP has no integrator fee parameter, and its adapter rejects native-fee requests. New policy applies only to newly prepared quotes; already prepared calls do not change.

`stock-eligibility.ts` guards stock buys against the trusted edge request country at prepare and confirm, including signed replays; sells to Base USDC remain reduce-only from any country. The private, session-authorized `GET /api/trades/stock-eligibility` reports buy eligibility and sell eligibility. Missing or invalid country returns `TRADE_STOCK_RESTRICTED` (403) for buys. The current any-token trade path excludes stocks. The single `provider-refusal.ts` classifier maps the exact token-authorization refusal to `TRADE_NOT_ROUTED`, minimum-amount refusals to `TRADE_BELOW_MINIMUM`, and other 400/404/422 CDP error bodies to `TRADE_ROUTE_UNAVAILABLE` without returning provider text; outages return `TRADE_UNAVAILABLE`.

`quote.ts` binds the exact pair, Permit2 spender and amount, recipient, receive minimum and registry Settler. Known Settler actions, pool restrictions, RFQ maker capacity and slippage checks fail closed; unknown later actions are admissible only behind a recognized exact permit-bearing first action and the registry router / outer recipient-token-minimum bounds. Unknown permit-bearing first actions remain unavailable. Its deterministic Settler input-spend model tracks fee and swap consumption in action order, assuming each AMM leg consumes its allotted input; known-only unprovable, underfilled or overfilled input yields a stale quote so retry requests a fresh route, and multi-leg router-funded routes model only V3 and RFQ legs. Unknown later actions report unmodeled spend and rely on the exact Permit2 ceiling plus Settler's atomic final slippage check, rather than claiming exact consumption. Pulled input can remain in Settler, bounded by `fromAmount`; unknown-action underfill can leave dust. An unknown action sending output directly to the taker rather than Settler is not rejected up front and deterministically reverts at Settler's final balance check, costing user gas or paymaster sponsorship. Admitted unknown-selector routes emit one structured `action-prepare` event (`TRADE_UNKNOWN_ACTIONS_ADMITTED`) containing only deduplicated unknown selectors and direction, without addresses, amounts or calldata. The strictly parsed UNISWAPV4_VIP first-action layout consumes the reviewed permit directly and accepts either buy or sell direction with identical permit, token, recipient and minimum bindings. Home removes the inner UNISWAPV2, MAVERICKV2, UNISWAPV3 and UNISWAPV4_VIP minimum-output words in the reviewed call; Settler's outer slippage record binds the reviewed minimum. `finalize.ts` verifies the reviewed owner signature and appends it to the exact pre-signature call. Quote expiration is bounded by the earliest permit deadline minus 30 seconds and two minutes from validation; confirm replay and retry refuse expired trades.

Provider refusals and an illiquid quote with a liquid reference-size price distinguish below-minimum from route-unavailable; failures of that secondary price check remain route-unavailable. The checkpoint (`bun run --cwd apps/web cdp-swaps:checkpoint --taker 0x… [--token 0x…] [--buy-usdc 1] [--sell 0.00001]`, or `--sweep --tokens 0xa,0xb,… --buy-usdc 0.10`) requests sanitized, non-funded quotes without signing or broadcasting. Chain failure still reports provider liquidity and action selectors, with unverified actions and exit 2. Funded buy/sell proof remains outstanding.
