# CDP Swaps on Base (#616)

`cdp-swaps.ts` requests USDC ↔ cbBTC executable quotes without signing or broadcasting. `permit2.ts` validates the exact Permit2 typed data and hash; `quote.ts` validates tokens, amounts, block freshness, approvals, gas, simulation, the current registry Settler, the recipient/buy-token/minimum-receive binding, and each supported Settler action. Unsupported selectors fail closed. Home zeros the inner UNISWAPV2, MAVERICKV2 and UNISWAPV3 minimum-output words in the reviewed call; Settler's outer slippage record alone binds the reviewed minimum. Pools are not allowlisted: exact Permit2 spend/spender and Settler's atomic slippage check protect the reviewed minimum. RFQ maker permits must name the receive token and provide enough base-unit capacity, after the larger of the quoted receive-token protocol fee and the fee-rate upper bound, to meet the reviewed outer minimum. RFQ-only routes must also have enough combined maximum taker spend to consume the full reviewed input; distinct maker nonces can combine. Mixed RFQ/AMM routes are rejected pending deterministic spend modeling. For AMM routes funded through Settler, one from-token swap must consume 100% of the remaining input; multi-action swaps are rejected, while direct pool prefunding does not leave input in Settler. RFQ output sent directly to the taker cannot satisfy Settler's final balance check. An expired maker permit is a stale quote.

`prepare.ts` verifies the session smart-account signer, requests a quote with a fresh key unrelated to the Home action id, then reads the Base block and Settler. At that pinned block it checks the taker's Permit2 nonce, verifies each RFQ maker's Permit2 witness signature (EOA or ERC-1271) and unused maker nonce, reads the taker's from-token balance and Permit2 allowance from chain, rejects insufficient balance, and builds an exact Permit2 approval only when chain allowance is short, followed by the pre-signature swap call. The shared action route prepends a network-fee approval if selected, records the final swap call index, and issues review with the effective execution deadline (earliest of taker and RFQ maker permit deadlines) minus 30 seconds, bounded by two minutes from quote validation. Confirm replay and retry are refused within 30 seconds of that effective deadline. Base Account signs Permit2 typed data; CDP embedded signs the Coinbase Smart Wallet permit hash. `finalize.ts` verifies the owner and appends the signature to the reviewed swap call. The paymaster callback matches only the confirmed exact batch.

`GET /api/trades` returns private, session-authorized availability: provider-unconfigured, account-unavailable, signer-unsupported, or available. The September 25 authenticated non-funded checkpoint passed for both directions (`docs/invest-data.md`). Bitcoin detail routes Buy/Sell through the trade dialog (`client/trading/`) when availability is `available`; funded live proof remains outstanding. The checkpoint command (`bun run --cwd apps/web cdp-swaps:checkpoint --taker 0x…`) emits only sanitized readiness facts and never signs or broadcasts.
